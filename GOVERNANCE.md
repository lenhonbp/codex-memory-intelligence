# Governance

Codex Memory Intelligence currently uses a maintainer-led governance model.

## Decision making

- Small fixes and documentation changes are decided through pull-request review.
- Public API, storage format, security boundary, and compatibility changes require a written design note in the pull request.
- Backward compatibility is preferred for `.codex-memory/` data. Breaking changes require migration guidance and a major release.
- Security fixes may be developed privately before coordinated disclosure.

## Maintainer responsibilities

Maintainers review contributions, keep releases reproducible, disclose limitations honestly, protect project security boundaries, and avoid vendor-specific lock-in unless clearly optional.

## Becoming a maintainer

Consistent, constructive contributions may lead to maintainer access. Existing maintainers decide by consensus based on technical judgment, reliability, community conduct, and security awareness.
